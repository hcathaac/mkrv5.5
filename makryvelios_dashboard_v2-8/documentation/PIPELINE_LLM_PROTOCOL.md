## Copy-ready prompts per stage

### Gate 0 — Preflight

Confirm source files, exact source names and sheets, units, code version, runtime and missing dependencies. Audit each dataset independently; show data types, missingness, duplicates, invalid values and key risks. Explain parser limitations (e.g. inferred identifier types). Do not assume equal row counts imply correspondence. Present a brief checkpoint, maximum six essential decisions, and request only missing evidence.

### Gate 1 — Cleaning and integration

Use the exact downloaded configuration keys. For every audited source propose native cleaning settings; preserve originals. Ask for approval of duplicate removal, missing tokens, numeric conversion and decimal conventions; never impute by default. Decide whether to keep separate, append matching schemas, join verified one-to-one keys, or align verified equally ordered observations. Explain observational unit, join coverage, missingness policy and why the join is valid. Return completed JSON; wait for approval. After execution, inspect post-clean audits and source hashes. Do not infer that missing observations are zero.

### Gate 2 — Literature and design

Inspect PDF page / DOCX block index. Request additional papers where gaps exist; search verified sources only with consent (existing journal/Zotero tools may help). Draft a grouped, stable RQ register (descriptive/associational/predictive/causal/scenario/qualitative/robustness), hypotheses and decision rules. Record source notes with an actual document label, numeric page/block and exact short extract, then explain relevance and limitations. Propose a tentative gap and contribution without claiming a comprehensive novelty search unless documented. Distinguish published estimates from new computed findings. Return only the approved-schema JSON for this stage.

### Gate 3 — Method plan and native execution

Read `pipeline_schema` or the schema JSON. Propose one to twenty analyses, each with id, method, complete `params`, `rq_ids`, source (`active` or exact cleaned source name), rationale, assumptions and figures flag. Recommend settings based on the data/design, not on attractive p-values. Explain seed, replication count, confidence, covariance, variable mapping, time/group design and multiplicity; ask at most six consolidated essential questions at once. No silent parameter changes. For Monte Carlo OLS, an illustrative candidate is `{"y":"actual_outcome","x_vars":["actual_predictor"],"simulations":2000,"method":"Wild bootstrap","confidence":0.95,"seed":42}`; replace with real mappings and confirm appropriateness. Do not call nonregistered methods through the pipeline. Where ITA/GAMS/MCDA or another native module is needed, request its actual native export and record it separately; do not represent it as a runner-native result. After human approval, execute only the approved stage and inspect full native tables, diagnostic results and figure index. A blocked result is not a result; request corrections/reapproval. Report association, prediction and causal identification separately; explain test meaning, effect size, uncertainty and limitations. OLS-family adjustment is only for that family; address other tests independently. Save checkpoint.

### Gate 4 — Critical manuscript synthesis

Use actual result table IDs, and complete the downloaded template. Write a coherent paper: abstract, gap, theory, RQs and hypotheses, methodology, results by RQ, robustness, critical discussion, contribution, policy/practical implications, conclusions, limitations, future research, declarations and verified references. Compare empirical and theoretical evidence critically: sample, units, period, estimand, specifications, magnitude, uncertainty and external validity. Answer each RQ once; distinguish not answerable / partly answered / answered. Assess every hypothesis using reject-null, fail-to-reject-null, consistent/inconsistent, inconclusive or not tested; never equate non-rejection with proof. For each numerical claim specify table ID, zero-based row position, exact column, reported numeric value and decimal rounding; include all numbers where possible. Never invent p-values, sources or confidence intervals. Explain which claims could not be verified. Bibliography is actual CSL/Zotero JSON (no invented DOI). Register unsupported conclusions explicitly. Submit draft and registers in the gate JSON; await numerical cross-check and approval. The runner checks listed values only, so human review must also compare manuscript prose and citations.

### Gate 5 — Editorial review

Run native structural peer review. Inspect every row, then independently simulate methods/statistical/editorial criticism grounded in actual evidence. Review identification, leakage, specification, multiplicity, sensitivity, numerical consistency, citations, journal style, limitations and disclosure. Propose precise revisions; use the manuscript revision operation if needed; do not change actual model outputs or approval records. Repeat review after revisions. If analyses need changing, start a new explicitly approved run, not a rewritten result table.

### Gate 6 — Publication package and handover

Address every native review row, document human verification of calculations, bibliography, ethics, confidential data and publisher requirements. Select only authorised artifact paths for the publisher candidate. Private checkpoint includes sources, original native code fingerprint, parameters/seeds, native result JSON/CSV, Excel, Word, LaTeX tables, actual figures/maps and interactive files where supported, RIS/BibTeX for Mendeley/Zotero, and review evidence. Parquet depends on installed dependency. Do not send private archive to a publisher. Review nested native ZIPs and row-level tables before sharing. Download the actual artifacts from the native UI or authorised runtime; an MCP result index is not a transferred file. Do not fabricate files, journal instructions, DOI or claims of execution. Finalise a concise handover with open limitations, where files are located, and the researcher review needed.

### Resume

Restore the trusted private checkpoint with the same code/environment; read next gate, approval and artifact index. Never redo an approved computation just because conversation context changed. Ask only for unresolved decisions. If checkpoint, code hash or environment differs, stop and identify the mismatch. A version upgrade may require a new run with the original input files and approved settings.
