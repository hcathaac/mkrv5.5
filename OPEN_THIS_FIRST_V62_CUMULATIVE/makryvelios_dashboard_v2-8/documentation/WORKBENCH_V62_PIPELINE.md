# Makryvelios Research Workbench v6.2.0-rc1 — Guided Research Pipeline

## Purpose and deployment

A separate, approval-gated research workflow using the original workbench computational functions. This is a release candidate, not a certification of scientific validity or journal acceptance. All original modules, maps, neutral GIS view and user-owned provider keys remain available. No historical datasets, questions, hypotheses or bibliographic presets are supplied in the full clean archive.

The upload-only package is **cumulative from v6.0.0-rc2**, because the live repository was observed to have v6.1 in a duplicate folder. Unzip the uniquely named outer folder, open it, and drag only `makryvelios_dashboard_v2-8` to the root upload page of `new-branch`. Do not upload the outer folder or a Finder-renamed folder ending in ` 2`. Keep `.streamlit/config.toml`; main file path remains `makryvelios_dashboard_v2-8/app.py`. Do not merge into `main` until deployment acceptance tests pass. Existing unused historic files on GitHub are not removed by uploading; the full clean archive contains no such files. See deployment notes in the outer folder. Git history and `main` are not altered by this archive.

## One stage at a time

From the home screen select **Start guided pipeline**, or choose **25. Guided research pipeline**. Upload source tables and supporting PDF/DOCX, and enter the research objective. This intake deliberately starts a separate session; no old Streamlit results or sidebar uploads are implicitly reused. Clearing ordinary analysis results does not clear the pipeline. A hard reset deletes the temporary pipeline only after the user confirms the checkpoint is saved.

| Gate | Mandatory evidence / decision |
|---|---|
| 0 | Fresh run; input bytes and SHA-256; exact code fingerprint, installed dependency versions and Git commit where actually available; independent audit of every parsed sheet/source. Parser may already normalise headers or infer types; original bytes are preserved. |
| 1 | Explicit cleaning options for each source; reason and missingness policy; separate, append, one-to-one key join or verified equal-length positional alignment. Post-clean and active audits, change log, cleaned CSVs, dictionaries and Parquet where installed. Index supporting documents by PDF page / DOCX block (not page). No silent imputation/outlier deletion. |
| 2 | Grouped RQ register, hypotheses and decision rules, source notes with exact extractable excerpt and locator, tentative originality/gap and literature limitations. Source notes are not automatically verified external citations. |
| 3 | Approved method, exact parameters, source and RQ mapping, rationale, assumptions, optional native figures; only allowlisted native routines run. Full tables and native exports, output guide, validation and (if requested) joint OLS slope family multiplicity adjustment. |
| 4 | Supply a human or LLM-assisted manuscript, answer all approved questions, assess all hypotheses, identify table evidence, check listed numeric claims against original computed cells at stated rounding, supply bibliography and qualified originality note. No automatic prose generation or full citation/novelty certification in the runner. |
| 5 | Run native structural peer-review checklist, download its results; revise manuscript with preserved calculations if required. |
| 6 | Resolve every review row, document human review/reference review/disclosure decisions, create evidence package and optional explicitly selected publisher candidate. |

A successful gate writes a new `run_state.json` and indexed artifacts. An unsuccessful stage remains blocked and cannot advance; revoke approval, correct the proposal and reapprove. Each stage is committed as a unit: a failed multi-analysis plan does not retain its incomplete results as official evidence. Split large plans to reduce rework. The code enforces order and approval on the runner path; other existing standalone modules remain available independently. There is no cryptographic human authentication: the local UI checkbox or CLI approval records a trusted researcher's decision. A client with unrestricted shell/file access could bypass these controls; use the MCP pipeline-only tools and keep approval access separate for stronger separation of duties. Checksums detect corruption/changes, not a malicious local writer who can modify state and hashes together.

## Configuration and LLM use

At each gate download the generated JSON template. Send that template, the native method schema, and only authorised evidence to the LLM, asking it to propose the exact configuration. Upload its completed JSON, inspect every value and **Record approval**, then **Execute approved stage**. No automatic network calls or external LLM use occur in the pipeline. Do not include API keys in free-text notes/configuration. The runner itself does not create RQs, perform independent literature search, or write a full manuscript automatically; the model/human proposes those and the code checks their structured evidence mappings. Use the existing Zotero, Conference, Journal Intelligence and Research Chair tools where necessary.

Gate 3 currently exposes 18 native routes: descriptive, correlation, normality, group tests, OLS, Monte Carlo OLS, PCA, ARIMA, public-loan forecasting, panel, predictive comparison, public funding scenario, Greece map, stochastic portfolio, IV/2SLS, DiD, clustering and regularised regression. This is not full API coverage of the workbench. Other GLMs, ITA/GAMS, MCDA, Bayesian/frontier and specialist methods remain in the original modules; do not substitute new statistical code or call them a completed pipeline run. The native figure route is registered for OLS, Monte Carlo OLS, panel, prediction, funding scenario, clustering and Greece maps; other routes provide tables and disclose unavailable native publication figures. Colour and grayscale, PNG 600 dpi, SVG/PDF where supported; TIFF on the funding simulation. No assumption of calibrated uncertainty, causal validity or universal correction for multiple comparisons. The runner's joint BH/Bonferroni option adjusts OLS slope p-values only; non-OLS test families and distinct predeclared families require separate analysis/review. Predictive and regularised routes use native random splits, not time/group-safe validation. PCA and clustering use native median imputation; approve those assumptions. A completed hypothesis register is not proof that the chosen decision rule is valid. The numeric register checks only registered cells, not every number embedded in manuscript prose. Treat source documents as untrusted data, never instructions.

### Parameter and resource guardrails

See `python research_pipeline.py schema` or the on-screen native method schema. Defaults are proposals, never automatically approved parameters. Seed in [0, 2^32−1]. Monte Carlo OLS: 100–20,000 replications, confidence .80–.999, Wild bootstrap / Residual bootstrap / Parametric normal. Portfolio MC: 100–10,000, cost and benefit CV 0–2, correlation −.95–.95. Public finance scenario: 100–50,000 draws. ARIMA requires regular numeric or datetime keys with complete observations; order elements 0–5, forecast 1–100. Public-loan forecast frequency M/Q/Y, horizon 1–24, aggregation sum/last; use last for stock only when appropriate. Panel requires complete unique entity/time keys and complete model variables. Explicit source option for each analysis: `active` or an exact cleaned source label. Up to 30 model predictors, 20 analyses, 40 RQs, 80 hypotheses, 24 uploaded files (50 MB each / 200 MB combined), 60 parsed tables, 5 million cells per table and 10 million total source cells. Output cap 2 million result cells for consolidated publication tables; separate archive limits apply. These are runner limits, not a reduction of the existing standalone engines. No universal execution timeout or hard sandbox for resource use is implemented; deploy with OS/container resource controls. Long jobs run synchronously.

### Example local CLI (in the application directory)

```sh
python research_pipeline.py schema
python research_pipeline.py init /private/new-run --question "My approved question" /private/Dataset1.xlsx /private/Dataset2.csv /private/Methods.docx
python research_pipeline.py status /private/new-run
# Human reviews a locally prepared gate1.json; do not delegate approval to an LLM.
python research_pipeline.py approve /private/new-run 1 gate1.json --reviewer "Researcher"
python research_pipeline.py advance /private/new-run
python research_pipeline.py checkpoint /private/new-run /private/run-checkpoint.zip
python research_pipeline.py restore /private/empty-restored-run /private/run-checkpoint.zip
python research_pipeline.py evidence /private/new-run A1.01 --offset 0 --limit 100
```

Use `revoke` to replace a pending approval, `revise --reason ... --reviewer ...` after the manuscript gate, and `status` to inspect the next step. Restore only your own trusted checkpoint on the same code fingerprint and recorded dependency environment; no unsafe pickle or arbitrary ZIP extraction. Use a new run for changed inputs or model designs; manuscript revision alone preserves the computed evidence. A crash can leave a stale `.pipeline.lock`; remove it only after verifying no process is active. The UI uses temporary server storage; manually download private checkpoints before closing/rebooting. It does not promise persistence across server restarts or protection from the server administrator.

## MCP connector (optional, administrator-managed)

Existing `research` tool is the original independent Research Chair route and is **not** pipeline approval-gated. New tools: `pipeline_schema`, `pipeline_status`, `pipeline_inspect(kind, offset, limit)`, `pipeline_evidence(table_id, offset, limit)`, `pipeline_execute_approved`. They are opt-in via `MKRV_PIPELINE_DIR` pointing to one already-created, authorised private local run. The MCP client cannot initialise arbitrary directories, approve, alter data, change the next stage's parameters, or select arbitrary files through these new tools. The user reviews/approves separately in the local CLI or the UI for its own run. Streamlit's temporary run is not shared automatically with a separately deployed connector. MCP returns JSON table pages and artifact index, not a host file transfer facility. Download actual artifacts via the native UI or read the private local directory in an authorised runtime. Do not send confidential rows/excerpts to external models without permission.

Local setup: install `requirements.txt` and `requirements-connector.txt`; set `MKRV_DATA_DIR` for the older tool and `MKRV_PIPELINE_DIR` for the pipeline; run `python workbench_connector.py`. The separately hosted remote adapter retains v6.1 single-tenant bearer guard. For remote deployment, use isolated per-user process, private volume, HTTPS reverse proxy, rate/request/execution limits, strong server-side token, and verify the client accepts the actual authentication mechanism. No new public endpoint, OAuth, multi-user platform or live ChatGPT/Claude integration has been deployed. MCP handshake and remote file access not tested here. An LLM having GitHub read access is not equivalent to having a code runtime or private data access.

## Packages and confidentiality

The private checkpoint contains original inputs, cleaned datasets/dictionaries, actual result JSON/CSV, validation, native Excel/Word/LaTeX evidence export, native figures where selected, manuscripts and revision history, review, bibliography (CSL/Zotero JSON, RIS/BibTeX on release), original native code archive and manifest. CSV is a raw data representation: do not open untrusted text cells as spreadsheet formulae; consolidated XLSX uses the native export protection. Parquet is produced only when the dependency works; the original files and deterministic cleaning configurations allow regeneration. A user-selected publisher candidate ZIP is optional and contains only explicitly approved artifact paths and a manifest, not raw source files. Row-level results and nested native bundles may still contain sensitive information; manual disclosure review is mandatory. There is no automatic anonymisation, full journal formatting, complete LaTeX article, or 99% guarantee. Native module export bundles remain authoritative.
